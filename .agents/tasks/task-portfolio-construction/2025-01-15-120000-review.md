# Quantitative portfolio construction library for Chinese A-shares

A greenfield Python package (`quant_portfolio`) delivering 100 trading strategies across 8 categories, 100 optimization algorithms across 7 categories, a backtesting engine with transaction-cost modeling, and a portfolio construction layer that wires signals to optimized weights. The architecture uses an abstract-base-class + `__init_subclass__` auto-registration pattern for both strategies and algorithms, with a separate registry module that imports all category packages to force registration at import time. The data layer wraps Baostock for Chinese A-share market data.

**Watch for:** The `num_trades` metric counts total bars rather than actual position changes (confirmed). The global mutable class-level registry dict introduces cross-test contamination risk and makes parallel test execution unsafe (confirmed). Several "ML" strategies are simplified heuristics rather than the algorithms their names imply (confirmed for `LSTMStrategy`). The backtester does not model portfolio-level capital allocation or leverage — it assumes a single-asset fractional position (confirmed).

## High-level view

The strategy/algorithm extensibility model uses `__init_subclass__` for auto-registration into a shared class-level dict. The tradeoff is that test classes register globally and persist for the session, leaking state between tests.

The backtesting engine models single-asset execution with one-period signal delay, proportional commission, and slippage. The `num_trades` metric is incorrectly wired to `returns.index.size` (total bar count) rather than the actual trade count.

The portfolio constructor bridges strategy signals to optimized weights via periodic rebalancing, forward-filling weights between rebalance dates. Signal lookup can silently use arbitrarily stale signals when the signal DataFrame has gaps.

The test suite validates the interface contract (signal shape, weight normalization, metric finiteness) across all 200 implementations using parametrized tests. Coverage is wide but shallow — it cannot catch numerical correctness issues in individual algorithm implementations. No tests verify algorithm behavior against known analytical solutions or degenerate inputs.

The data layer is a thin Baostock wrapper with no caching, rate-limit handling, retry logic, or mock injection point, making it untestable in CI.

<summary>Issues (7)</summary>

1. **`num_trades` reports bar count, not trade count** — In `Backtester._compute_metrics`, `"num_trades"` is set to `returns.index.size` (length of the entire series). Change it to `int((trades_mask > 0).sum())` or `len(trade_indices)`.
2. **Global mutable registry is shared across tests** — `AlgorithmRegistry._registry` and `StrategyRegistry._registry` are class-level dicts. Tests that register ad-hoc classes (like `EqualWeightAlgorithm` in `test_portfolio_constructor.py`) pollute the global state. Use a fixture-scoped registry copy or inject the registry as a dependency.
3. **LSTM strategy is a weighted moving average, not an LSTM** — `LSTMStrategy.generate_signals` computes an exponential-weighted sum of recent returns, which is an EMA filter. The name misleads users expecting recurrent network behavior.
4. **Black-Litterman without views collapses to inverse-variance** — The implementation short-circuits when no views are provided, returning `(1/lambda) * Sigma^{-1} * pi`. The docstring implies view incorporation is active but no API exists to pass views.
5. **Backtester is single-asset only** — Multi-asset portfolio backtesting (where `PortfolioConstructor` produces weights across assets) has no built-in P&L simulation. Position sizing, turnover constraints, and cross-asset slippage are not modeled.
6. **No data-layer testability** — `BaostockProvider` has no interface abstraction or mock injection point. The test file only checks method existence.
7. **Copula arbitrage strategy is a quantile rank filter** — `CopulaArb` computes a min-max normalized rank of the current return within a rolling window. No copula function is fit, no marginal distributions are transformed.

## Registry state leakage

`_registry` is a plain class-level `Dict[str, Type]` shared across the entire process. In `tests/test_portfolio_constructor.py`, the test defines `EqualWeightAlgorithm` with `name = "EqualWeight"`, which registers globally and persists for the rest of the test session. If another test later calls `AlgorithmRegistry.list_algorithms()`, it will include this test-only class. The `clear()` method exists but isn't called in test teardown, and calling it would destroy all real registrations. A fixture-scoped registry copy or a registry instance (rather than class-level state) would isolate test pollution.

## Backtester `num_trades` bug

The bug is in `_compute_metrics`:

```python
"num_trades": int(returns.index.size),
```

This returns the total number of bars (e.g., 252 for a year of daily data), not the number of trades. The correct value is `int((trades_mask > 0).sum())`, but `trades_mask` is not passed to `_compute_metrics`. The fix requires either passing the trade count as an argument or computing it within `run()` before calling `_compute_metrics`.

Transaction costs scale linearly with position-change magnitude — going from +1 to -1 incurs double cost (diff = 2). This is a reasonable round-trip approximation, but combined with a single-asset model it means the backtester cannot simulate multi-asset rebalancing costs (turnover across the portfolio).

## ML strategy naming vs. implementation

`LSTMStrategy` applies a fixed exponential weight vector to the last `lookback` returns and thresholds at 0.001:

```python
weights = np.exp(np.linspace(-1, 0, self.lookback))
weights /= weights.sum()
pred = np.dot(weights, window)
```

No hidden state, no gating mechanism, no learned parameters. Similarly, `CopulaArb` computes a min-max rank within a window — no copula function is fit, no dependence structure is modeled. By contrast, `RandomForestStrategy` genuinely trains a `RandomForestClassifier` in a rolling window, demonstrating the pattern is implementable within the framework.

## Stale signal risk in portfolio constructor

The signal lookup when the rebalance date doesn't align with a signal date:

```python
valid_signal_dates = signals.index[signals.index <= date]
current_signals = signals.loc[valid_signal_dates[-1]]
```

This forward-fills signals with no staleness bound. If the signal DataFrame has a multi-week gap (e.g., due to missing data or a strategy that only generates signals monthly), the constructor will silently use week-old or month-old signals without warning.

## HRP clustering method divergence

`HierarchicalRiskParityOptimization` uses single-linkage clustering (`method="single"`), where the original Lopez de Prado paper specifies Ward's method. Single linkage is sensitive to outliers and produces chain-like clusters. On assets with heterogeneous correlation structures, this will produce meaningfully different allocations than the canonical algorithm. The divergence is likely unintentional.

## RL algorithm convergence concern

`ReinforcementLearningAlgorithm` uses tabular Q-learning with 3 discrete states and 10 random action vectors, training for 50 episodes over ~250 data points. The Q-table has only 30 entries. With epsilon-greedy exploration at 0.1, each state-action pair gets approximately `50 * 230 * (0.9/10 + 0.1/10) = ~1150` updates total, spread across 30 cells. Convergence is possible given the small state space, but the 10 random action vectors (drawn once from Dirichlet at initialization) mean the algorithm can only ever select from a fixed set of allocations — it cannot interpolate between them. The output quality depends entirely on whether one of the 10 random draws happens to be close to optimal.

## Test coverage gaps

Not tested: individual algorithm correctness against known analytical solutions (e.g., equal-weight benchmark for 1/N, analytical min-variance for 2-asset case), behavior under degenerate inputs (singular covariance, zero-variance assets, all-NaN columns, single-row DataFrames), performance under realistic data sizes (1000+ assets), or the Baostock provider against a live or mocked API.
